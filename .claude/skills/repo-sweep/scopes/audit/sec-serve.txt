Security audit of how a session is served and recorded: kamchatka/src/remote/server/mod.rs (the bind), the record directory in kamchatka/src/wiring/ (mod.rs, record.rs), and the page in kamchatka/src/web/ (`--web`, and the gateway example built on it), against SECURITY.md (read it first; its claims are what is under audit). Check, quoting the deciding lines: that `--serve` and `--web` each refuse every non-loopback address, including IPv6 forms, IPv4-mapped IPv6, `0.0.0.0`, a hostname that resolves to something else, and a unix path; when and how the socket file is made 0600 and what a pre-existing file or link at that path does; the record directory's checks (0700, owner, what happens if the name is a link, a file, or a directory another user owns) and whether a failed check writes nothing; the page's port being closed to confined commands while it listens; the page's checks on host, origin and content type, and whether a request from a web page in a browser on the same machine can pass them (a missing Origin, `null`, a DNS name that resolves to 127.0.0.1, a simple request that needs no preflight). Report verified defects only.
